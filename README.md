# SPREAD // Spot-Perp Scanner

Сканер разницы между спотовой ценой и ценой бессрочного фьючерса (perp)
по альткоинам сразу на трёх площадках: **Binance · Bybit · MEXC**.
Показывает спред (абс. и %), фандинг и объёмы 24ч по всем листингам в одной
таблице. Не инвестиционная рекомендация — только инструмент наблюдения за рынком.

---

## Как работает проект

В репозитории две редакции одного и того же сканера.

### Редакция 1 — Static (основная, `index.html`)

```
Браузер (ваш домашний IP)
   │  каждые 30 сек — лёгкие запросы: цены спота/перпов + фандинг (все биржи)
   │  каждые 60 сек — «тяжёлые» /ticker/24hr: объёмы и Δ24ч (Binance, MEXC)
   ▼
Binance · Bybit · MEXC (публичные API, без ключей)
```

- Один HTML-файл: открывается локально (`file://`), без сервера, Firebase и ключей.
- **MEXC — основная биржа**: фильтр «ПЕРП» по умолчанию стоит на MEXC;
  приоритет спота: своя биржа перпа → MEXC → Binance → Bybit.
- Кэш в `localStorage`: после перезагрузки таблица мгновенно показывается из
  кэша, сверху доезжают свежие данные.
- Сортировка кликом по «Спред %», «Фандинг %», «24ч Δ %»; фильтры: поиск,
  биржа перпа, объём, мин/макс |спред|, «только пары со спотом», исключение
  топ-монет по рангу, лимит строк.
- ⚠️ **Для MEXC нужно расширение-обходчик CORS** (раздел ниже) — иначе браузер
  блокирует ответ API. Binance и Bybit работают без него.

### Редакция 2 — серверная (Firebase, без CORS вообще)

```
Binance · Bybit · MEXC
        │  fetch (self-hosted раннер = ваш ПК, домашний IP)
        ▼
GitHub Actions (cron ~раз в 5 минут)
        │  запись через firebase-admin + сервисный аккаунт
        ▼
Firebase Realtime Database (Spark, бесплатно)
        │  чтение через Firebase JS SDK, onValue()
        ▼
index.html (Firebase-редакция)
```

- Поллер `scripts/poll-spreads.js` опрашивает три биржи и пишет единым блоком
  в путь `spreads`: `updatedAt`, `status{binance,bybit,mexc}`, `rows[]`.
- Запускается на **self-hosted раннере** — запросы идут с домашнего IP и не
  блокируются биржами как трафик дата-центра.
- Приоритет спота в этой схеме: Binance → своя биржа перпа → любая другая
  (источник указан в каждой строке как `spotSource`).
- Страница только читает базу; обновление ~раз в 5 минут (минимум cron GitHub
  Actions). Краткая настройка — раздел «Серверная схема: настройка» ниже.

### Состав репозитория

| Файл | Назначение |
| --- | --- |
| `index.html` (static) | основная статичная редакция сканера |
| `scripts/poll-spreads.js` | серверный поллер для Firebase-схемы |
| `.github/workflows/` | cron-воркфлоу поллера |
| `database.rules.json` | правила RTDB: публичное чтение, запись закрыта |
| `package.json` | зависимости поллера (`firebase-admin`) |

## ❗ ГЛАВНОЕ (для static-редакции): ДЛЯ MEXC НУЖНО РАСШИРЕНИЕ-ОБОХОДЧИК CORS

### Почему без него не работает
- **Binance и Bybit** шлют заголовок `Access-Control-Allow-Origin: *` —
  браузер разрешает читать их API напрямую. Расширение для них НЕ нужно.
- **MEXC** этот заголовок НЕ шлёт. Запрос до сервера доходит и данные приходят,
  но браузер блокирует ответ (красная ошибка CORS в консоли).
- WebSocket-подписка MEXC блочится ещё и на стороне сервера (`Reason: Blocked!`),
  поэтому рабочий канал из браузера только один: **HTTP + расширение**.

### Что поставить (Chrome Web Store, работает и в Brave)
1. **Allow CORS: Access-Control-Allow-Origin** (автор Mylen) — основное;
2. **CORS Unblock** (acytoo) — запасной вариант, если первое не сработало.

### Порядок действий
1. Установить расширение.
2. Кликнуть по его иконке — должна стать «активной».
3. Перезагрузить страницу сканера (F5).
4. Кнопка `mexc` в шапке должна позеленеть: `mexc ✓`.
5. **После работы — выключить расширение!** Оно ослабляет защиту браузера на
   ВСЕХ сайтах, а не только в сканере. Не держать включённым во время входа в
   аккаунты бирж. (Лайфхак: отдельный профиль Brave под сканер.)

### Как проверить, что всё ок
- F12 → Console: нет красных ошибок CORS по `api.mexc.com` / `contract.mexc.com`.
- Если красное появилось — расширение выключено или не сработало.

## Обновления и нагрузка (static)
- **30 сек** — лёгкие запросы ко всем включённым биржам (цены + фандинг).
- **60 сек** — «большие данные»: `/ticker/24hr` у Binance и MEXC (объёмы, Δ24ч).
  Bybit отдаёт объёмы сразу в лёгком тикере.
- Итого ~7 лёгких запросов за 30-сек цикл + 3 тяжёлых раз в минуту — доли
  процента от лимитов бирж, риска бана нет.

## Управление
- Кнопки `mexc / binance / bybit` в шапке — вкл/выкл биржи (сохраняется в
  localStorage).
- Фильтры: поиск, биржа перпа, мин/макс |спред|, объём 24ч, «только пары со
  спотом», исключение топ-монет по рангу, макс. строк.
- Сортировка кликом по заголовкам: «Спред %», «Фандинг %», «24ч Δ %»
  (1-й клик — по убыванию, 2-й — по возрастанию, 3-й — сброс).

## Серверная схема: краткая настройка (если расширение надоест)

1. **Firebase**: console.firebase.google.com → Add project, оставайся на
   бесплатном Spark (Blaze не нужен — Cloud Functions не используются).
2. Build → Realtime Database → Create Database; скопируй Database URL
   (`https://ТВОЙ-ПРОЕКТ-default-rtdb.firebaseio.com`); правила перезапиши
   `database.rules.json` (публичное чтение, запись только сервисным аккаунтом —
   Admin SDK правила игнорирует).
3. Project settings → Service accounts → Generate new private key — скачанный
   JSON это и есть `FIREBASE_SERVICE_ACCOUNT`. Никому не показывай ключ.
4. Создай репозиторий на GitHub, скопируй `scripts/`, `.github/workflows/`,
   `package.json` с сохранением структуры.
5. Settings → Secrets → Actions: добавь `FIREBASE_SERVICE_ACCOUNT` (весь JSON
   как есть) и `FIREBASE_DATABASE_URL`.
6. `git push` активирует воркфлоу; вручную: Actions → Poll spot/perp spreads →
   Run workflow. Проверка: RTDB → Data → узел `spreads`.
7. Фронтенд: Project settings → Your apps → `</>` → скопируй `firebaseConfig`
   и вставь в Firebase-редакцию `index.html` вместо плейсхолдеров.

### Частые проблемы
- Таблица пуста — воркфлоу ещё не отработал, запусти вручную.
- Ошибка чтения на странице — неверный `databaseURL`/`apiKey` или не применились
  правила базы.
- Job падает по авторизации — `FIREBASE_SERVICE_ACCOUNT` вставлен не целиком
  или с лишними пробелами.

## Мелочи (не баги, static)
- `favicon-*.png: ERR_FILE_NOT_FOUND` — рядом с html нет файлов иконок,
  на данные не влияет.
- `Unsafe attempt to load URL file://…` — предупреждение браузера о том, что
  страница открыта с диска; лечению не подлежит и не мешает.
